## Threat model

Careless or accidental worker behaviour plus secret exposure. Deliberate attacks that
need several launches to set up (plant on run 1, exploit on run 2) are accepted, except
the planted-symlink case, which is closed.

## Accepted gaps (shipped as known)

- `fleet land` on the host sources `remote/<ws>.env` files a worker could have written.
- git rebase / sequencer todo files (`exec` lines) a worker leaves in `.git` run when the
  host continues that rebase.
- libgit2 / gitoxide are untested with the `.git/commondir` "." placeholder.
- A `noscan:` folder gets no secret-file scan, and nested repos and sockets inside it are
  not checked (its top-level `.git` still is).

- Nested `sub/.claude` and `sub/.git` below the root (or an opening) are not protected;
  dangerous only if the host later runs Claude or git from that subfolder.
- Placeholders stay on the host after a run: `.mcp.json` (`{"mcpServers":{}}`, locally
  excluded from git), empty `.claude` / `.git` stand-in dirs in openings, `.git/commondir`
  (".") and empty `config.worktree` files. Deleting them would detach the read-only
  mounts of other workers still running on the same tree. `.git/commondir` "." was
  checked with git 2.43 (status, add, commit, branch, worktree add/list); other git
  implementations (libgit2, gitoxide) were not tested.
- Workers cannot add new top-level entries under `planning/`.
- Fleet spawn still discovers the newest run dir when `FLEET_RUN_DIR` is unset; guarded by
  the read-only `planning/` top level and the registry command check.
- No MCP servers, npm/pip/GitHub network, Windows interop or mailbox listener inside.
- Worker homes under `~/.claude/zai-workers` (about 184 KB each) are not reaped.
- macOS: Seatbelt unchanged; a symlinked `.env` is not masked there.
- `spawn-remote.sh` (host lanes) still interpolates engine args into the pane command.

## 1. Why

The Linux backend binds `/` read-only and hides parts (deny-list); every review round found
a new unhidden path. An allow-list closes the class: anything not listed is absent.

## 2. Model

bwrap starts from an empty tmpfs root (`--tmpfs /`), `--new-session`, `--unshare-all`
(user, pid, ipc, uts, cgroup, NET), fresh `--dev /dev`, `--proc /proc` (pid namespace: no
host pids, so no `/proc/<host-pid>/{root,environ,fd}`), no `/sys`.

Mount phases, strict, later wins:
(a) system ro + private state rw + root rw + rw openings (each opening pinned by fd);
(b) root and every opened repo: `.git/config*`, `.git/hooks`, `core.hooksPath` and
    `include.path` targets ro; project `.claude` dirs ro except their non-config children;
(c) ro: openings (pinned by fd), `.zai-fence-readonly` entries;
(d) TRUSTED RUNTIME ro: `~/.claude` subset and the real targets of its symlinks
    (cfn-scripts, skills, hooks... in this repo through reverse links), after every
    project bind, so a worker can never rewrite the launcher or approval code;
(e) secret masks (section 3.5), then credential masks LAST.

## 3. Fixes

1. **`--bin`**: resolved once to an absolute realpath (bare names via PATH, relative PATH
   entries skipped); the pane execs that absolute path. The fence wrapper is always the
   installed realpath, never from `--bin` or PATH.
2. **Launcher input**: `--args`/`--model`/registry args split into words and written with
   `printf %q` (execute.sh and cmd-spawn.sh); never pasted raw into shell code.
3. **Policy integrity = approval store** (git object rehash dropped: SHA-256 approval covers
   forged bytes). `glm-open-approve.sh` (host only) writes
   `~/.config/cfn-fleet/glm-open/<rootid>.sha256`, `rootid` = sha256 of the root realpath
   (collision-free, unlike the slug). Writer rules: owned by the user, dir 0700, file 0600,
   temp file + `mv` (atomic), refuses a symlinked or foreign-owned store. Readers refuse a
   store that is group/world-writable or not owned by the user. `~/.config` is absent in
   the fence, and an opening can never contain it (credential path validation).
   Launch refuses unless sha256(HEAD policy content) equals the approved value.
4. **Pin openings by descriptor**: open each opening (and the root) as a directory fd,
   check `/proc/self/fd/N` resolves to the validated realpath, scan `.env` etc. through
   that fd, and mount it with `--bind-fd/--ro-bind-fd`: a rename/symlink swap between
   validation and bind cannot change what is mounted. bwrap closes those fds (test).
5. **Inherited fds**: the fence closes every fd above 2 before exec, except the pinned
   directory fds handed to bwrap (which bwrap closes after mounting).
6. **Network / IPC** (decision for the user, see 3.6 below).
7. **Sanitized config** (table above); opened repos get the same git hook/config
   protection as the root; a `core.hooksPath`/`include.path` target that does not exist
   yet inside a writable tree refuses launch.
8. **Secrets inside openings**: masked by name in every opening (rw or ro):
   `.env .env.* .envrc .dev.vars *.local.json settings.local.json .npmrc .pypirc .netrc
   .git-credentials credentials credentials.json credentials.*.json service-account*.json
   *.pem *.key *.p12 *.pfx id_rsa* id_ed25519* id_ecdsa* .aws .docker .ssh .vercel
   .supabase secrets.* *.tfstate*`. Fence root: `.env*` and `settings.local.json`.
   Scans fail closed (any find error or timeout = exit 70). tmux / docker sockets found
   in a mounted tree refuse launch.

### 3.6 Network: **Needs your decision (default chosen: broker)**

No slirp4netns/pasta/socat on this host. Default implemented: `--unshare-net` (no host
loopback, no abstract sockets, no tmux sockets reachable) plus a small python broker:
host side accepts only `CONNECT api.z.ai:443` on a unix socket bound into the fence; an
in-fence relay listens on `127.0.0.1:<port>` and the worker gets `HTTPS_PROXY`. Effect:
the worker reaches z.ai and nothing else (no npm, pip, cargo, WebFetch, GitHub).
Escape hatch: `ZAI_FENCE_NET=host` keeps the shared network (old behaviour, warns).
If the broker proves unreliable in the trace run, fall back to `ZAI_FENCE_NET=host` as
default and record it here as an ACCEPTED GAP.
