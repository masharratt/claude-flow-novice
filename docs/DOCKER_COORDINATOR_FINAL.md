# Docker Coordinator - Final Implementation ✅

## Executive Summary

**Slash command `/cfn-docker-native` now launches the Docker coordinator as a container where the coordinator:**
1. ✅ **Plans dynamically** via Anthropic API calls in orchestrate.sh
2. ✅ **Decomposes tasks** into atomic units (15-30 min scopes)
3. ✅ **Launches Docker sub-agents** via Docker-in-Docker
4. ✅ **Assigns atomic tasks** to each worker agent

## Complete Architecture

```
User: /cfn-docker-native "Implement authentication"
    ↓
Main Chat: docker run cfn-coordinator:v3
    ↓
Container: coordinator-entrypoint.sh
    ↓ Validates: Docker socket, Redis, codebase mount, API key
    ↓
orchestrate.sh execute
    ↓
plan_task() function:
    ├─ Has ANTHROPIC_API_KEY? → Call API for planning
    ├─ Generate: /tmp/cfn-docker-plan-*.json
    └─ Parse: Extract agent assignments
    ↓
spawn_loop3():
    ├─ Read plan file
    ├─ For each agent: assign atomic task from plan
    └─ spawn-agent.sh → docker run (workers)
    ↓
Worker Agents (Docker containers):
    ├─ Receive: atomic task context (15-30 min scope)
    ├─ Execute: specific deliverables
    └─ Report: confidence scores to Redis
    ↓
Gate Check → Loop 2 Validators → Product Owner Decision
```

## Key Implementation Details

### 1. Planning via API in orchestrate.sh

**File:** `.claude/skills/cfn-docker-loop-orchestration/orchestrate.sh`
**Function:** `plan_task()` (lines 252-393)

**Logic:**
```bash
# Check if plan file exists (pre-planning)
if [[ -f "$plan_file" ]]; then
    use existing plan
fi

# Generate plan via API (Docker mode with API key)
if [[ -n "${ANTHROPIC_API_KEY:-}" ]]; then
    curl Anthropic API with planning prompt
    parse JSON response
    save to /tmp/cfn-docker-plan-*.json
fi

# Fallback: wait for external plan (Task mode)
else
    wait 30 seconds for plan file
    fall back to keyword matching
fi
```

### 2. Atomic Task Assignment

**File:** `.claude/skills/cfn-docker-loop-orchestration/orchestrate.sh`
**Function:** `spawn_loop3()` (lines 451-509)

**Logic:**
```bash
for agent_type in agents; do
    # Read atomic task from plan
    atomic_task_desc=$(jq plan for this agent_type)
    atomic_task_deliverables=$(jq deliverables)

    # Create context with atomic task
    cat > context_file << EOF
    {
        "atomic_task": "$atomic_task_desc",
        "expected_deliverables": "$atomic_task_deliverables",
        "estimated_time": "15-30 min"
    }
    EOF

    # Spawn worker with atomic task context
    spawn-agent.sh --context-file context_file
done
```

### 4. Slash Command

**File:** `.claude/commands/cfn-docker/CFN_DOCKER_NATIVE.md`
**Command:** `/cfn-docker-native "task" --mode=standard`

**Steps:**
1. Parse arguments, generate task ID
2. Ensure Redis running
3. Build coordinator image (if needed)
4. Spawn coordinator container:
   ```bash
   docker run --rm \
     --name "cfn-coordinator-${TASK_ID}" \
     --network mcp-network \
     --volume /var/run/docker.sock:/var/run/docker.sock \
     --volume $(pwd):/app/codebase:ro \
     --volume /tmp:/tmp \
     --env ANTHROPIC_API_KEY="${ANTHROPIC_API_KEY}" \
     --env TASK_ID="${TASK_ID}" \
     --env TASK_DESCRIPTION="${TASK_DESCRIPTION}" \
     --env MODE="${MODE}" \
     cfn-coordinator:v3
   ```
5. Monitor execution, report results

## What Makes This Work

### Planning Happens in Container ✅

The coordinator container has:
- ✅ ANTHROPIC_API_KEY environment variable
- ✅ curl to call Anthropic API
- ✅ jq to parse JSON responses
- ✅ orchestrate.sh with `plan_task()` function that calls API
- ✅ /tmp mount to write plan files

**Result:** Container generates its own execution plan dynamically.

### Worker Spawning via Docker-in-Docker ✅

The coordinator container has:
- ✅ /var/run/docker.sock mounted (Docker client in container)
- ✅ spawn-agent.sh from mounted codebase
- ✅ Access to `docker run` command
- ✅ mcp-network to communicate with workers

**Result:** Coordinator spawns worker containers from inside its own container.

### Atomic Task Assignment ✅

The `spawn_loop3()` function:
- ✅ Reads plan file generated by `plan_task()`
- ✅ Extracts atomic task for each agent type
- ✅ Creates agent-specific context file with atomic task
- ✅ Passes context to spawn-agent.sh

**Result:** Each worker gets exactly ONE scoped task (15-30 min).
