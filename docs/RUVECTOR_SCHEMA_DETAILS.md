## Collection 1: Decompositions

### Purpose

Stores how complex tasks are broken down into components. Enables learning how similar tasks were previously decomposed.

### Schema Definition

```typescript
interface DecompositionRecord {
  // Auto-generated fields
  id: string;                          // Unique identifier (UUID)
  createdAt: Date;                     // Creation timestamp
  updatedAt: Date;                     // Last modification timestamp

  // Core fields
  taskId: string;                      // Reference to original task
  agentType: 'implementer' | 'validator' | 'coordinator';
  status: 'in_progress' | 'completed' | 'failed' | 'aborted';

  // Decomposition details
  components: string[];                // List of task components identified
  estimatedComplexity: 'simple' | 'moderate' | 'complex';
  estimatedDurationSeconds?: number;   // Estimated execution time
  actualDurationSeconds?: number;      // Actual execution time if completed

  // Metadata
  metadata: {
    timestamp?: string;                // ISO8601 timestamp
    version?: string;                  // Schema version
    model?: string;                    // AI model used (e.g., "claude-3-sonnet")
    loopIteration?: number;            // Which loop created this
    agents?: Array<{
      type: string;
      count: number;
    }>;
    dependency?: Record<string, string[]>;  // Component dependencies
    tags?: string[];
    [key: string]: any;                // Custom metadata
  };
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Auto | UUID generated by system |
| `taskId` | string | Yes | Original task identifier |
| `agentType` | enum | Yes | Which agent type created the decomposition |
| `status` | enum | Yes | Current status of the decomposed task |
| `components` | string[] | Yes | Ordered list of task components |
| `estimatedComplexity` | enum | Yes | Complexity assessment (drives loop selection) |
| `estimatedDurationSeconds` | number | No | Initial time estimate in seconds |
| `actualDurationSeconds` | number | No | Actual time taken (if completed) |
| `metadata.timestamp` | string | No | ISO8601 creation time |
| `metadata.model` | string | No | Model used for decomposition |
| `metadata.loopIteration` | number | No | Which loop iteration (1, 2, or 3) |
| `metadata.agents` | object[] | No | Participating agents and counts |
| `metadata.tags` | string[] | No | Classification tags |

```typescript
const similar = await client.query.semanticSearch(
  'decompositions',
  'Quick data validation task',
  10
);
```

```typescript
const fastComplex = await client.decompositions.list({
  limit: 50,
  filter: {
    estimatedComplexity: 'complex',
    actualDurationSeconds: {$lt: 7200}
  }
});
```

## Collection 2: Errors

### Purpose

Tracks error patterns discovered during task execution. Builds a knowledge base of solutions.

### Schema Definition

```typescript
interface ErrorPatternRecord {
  // Auto-generated fields
  id: string;                          // Unique identifier (UUID)
  createdAt: Date;                     // First occurrence timestamp
  updatedAt: Date;                     // Last occurrence timestamp

  // Error details
  errorType: string;                   // e.g., "ValidationError", "TimeoutError", "MemoryError"
  message: string;                     // Error message (should be normalized)
  context: {
    field?: string;                    // Affected field (if applicable)
    expectedType?: string;             // Expected type
    receivedValue?: string;            // Actual value (redacted if sensitive)
    receivedType?: string;             // Type received
    taskId?: string;                   // Associated task
    agentId?: string;                  // Which agent encountered it
    stackTrace?: string;               // First few lines of stack trace
    [key: string]: any;                // Custom context
  };

  // Frequency and history
  frequency: number;                   // Number of times encountered
  firstOccurred: Date;                 // When first seen
  lastOccurred?: Date;                 // When last seen
  occurrencePercentile?: number;       // Percent of tasks that encounter this

  // Solutions and remediation
  solutions: string[];                 // Known fixes/workarounds
  rootCauseAnalysis?: string;          // Identified root cause
  preventionStrategies?: string[];     // How to prevent recurrence

  // Status tracking
  status: 'open' | 'in_progress' | 'resolved' | 'documented' | 'archived';
  relatedTaskIds?: string[];           // Tasks affected by this error
  relatedIssueIds?: string[];          // External issue references
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `errorType` | string | Yes | Normalized error class name |
| `message` | string | Yes | Error message (normalized) |
| `context` | object | Yes | Contextual information about error |
| `frequency` | number | Yes | How many times this error has occurred |
| `solutions` | string[] | Yes | Known fixes (at least one) |
| `status` | enum | Yes | Current status of error tracking |
| `lastOccurred` | Date | No | When error was last seen |
| `rootCauseAnalysis` | string | No | Root cause if determined |
| `preventionStrategies` | string[] | No | How to prevent future occurrences |

### Query Patterns

**Find solutions for a new error:**
```typescript
try {
  await riskyOperation();
} catch (err) {
  const similar = await client.query.semanticSearch(
    'errors',
    err.message,
    3
  );
  console.log(`Solutions: ${similar[0]?.solutions[0]}`);
}
```

**Find most common errors:**
```typescript
const commonErrors = await client.errors.list({
  limit: 20,
  sortBy: 'frequency',
  sortOrder: 'desc'
});
```

**Find unresolved errors:**
```typescript
const unresolved = await client.query.filterSearch(
  'errors',
  { status: {$in: ['open', 'in_progress']} },
  100
);
```

## Collection 3: Security

### Purpose

Records security findings, vulnerabilities, and their remediation. Prevents recurrence of known issues.

### Schema Definition

```typescript
interface SecurityFindingRecord {
  // Auto-generated fields
  id: string;                          // Unique identifier (UUID)
  createdAt: Date;                     // Finding created timestamp
  updatedAt: Date;                     // Last update timestamp

  // Finding identification
  title: string;                       // Short description
  description: string;                 // Detailed description
  type: 'injection' | 'auth' | 'crypto' | 'exposure' | 'validation' | 'other';
  severity: 'low' | 'medium' | 'high' | 'critical';
  cvss?: number;                       // CVSS score (0-10) if applicable

  // Location and scope
  affectedComponent: string;           // File path or component identifier
  affectedComponentType?: 'file' | 'function' | 'class' | 'module' | 'service';
  discoveryMethod: 'automated' | 'manual' | 'validation' | 'audit' | 'external';

  // Status and remediation
  status: 'open' | 'in_progress' | 'resolved' | 'mitigated' | 'accepted_risk';
  mitigation?: string;                 // How it was fixed
  mitigationDate?: Date;               // When fixed
  remainingRisk?: 'low' | 'medium' | 'high';

  // Metadata
  metadata: {
    cwe?: string;                      // CWE identifier
    references?: string[];             // External references (CVE, etc.)
    discoveredBy?: string;             // Who found it
    reviewedBy?: string[];             // Who reviewed the fix
    tags?: string[];
    [key: string]: any;
  };

  // Tracking
  relatedFindings?: string[];          // Related security issues
  testCaseId?: string;                 // Test that validates fix
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | Brief finding summary |
| `description` | string | Yes | Detailed explanation |
| `type` | enum | Yes | Category of vulnerability |
| `severity` | enum | Yes | Impact level |
| `affectedComponent` | string | Yes | Where vulnerability exists |
| `status` | enum | Yes | Current remediation status |
| `discoveryMethod` | enum | Yes | How finding was discovered |
| `cvss` | number | No | CVSS severity score |
| `mitigation` | string | No | Description of fix |
| `metadata.cwe` | string | No | CWE identifier |
| `metadata.references` | string[] | No | External references |

## Collection 4: Performance

### Purpose

Stores execution metrics and performance data. Identifies bottlenecks and optimization opportunities.

### Schema Definition

```typescript
interface PerformanceMetricRecord {
  // Auto-generated fields
  id: string;                          // Unique identifier (UUID)
  createdAt: Date;                     // Recording timestamp
  updatedAt: Date;                     // Last update timestamp

  // Task reference
  taskId: string;                      // Task being measured
  timestamp: Date;                     // When measurement was taken

  // Core metrics
  executionTimeMs: number;             // Total execution time in milliseconds
  memoryUsageMb: number;               // Peak memory usage in MB
  cpuPercentage: number;               // CPU utilization percentage (0-100)
  memoryPeakMb?: number;               // If different from average

  // Detailed breakdown
  timingBreakdown?: {
    [phase: string]: number;           // Time spent in each phase (ms)
  };

  // Resource usage
  resourceUsage?: {
    diskIoMb?: number;                 // Disk I/O operations
    networkMb?: number;                // Network data transferred
    threadsCreated?: number;           // Concurrent threads
  };

  // Context
  metadata: {
    agentType?: string;                // Type of agent
    complexity?: 'simple' | 'moderate' | 'complex';
    iterations?: number;               // Number of iterations
    version?: string;                  // Code version/commit
    environment?: string;              // dev, staging, prod
    modelUsed?: string;                // AI model if applicable
    tags?: string[];
    [key: string]: any;
  };

  // Analysis
  isOptimal?: boolean;                 // Compared to baseline
  baselineMs?: number;                 // Expected execution time
  deviationPercent?: number;           // Variance from baseline
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `taskId` | string | Yes | Task identifier |
| `timestamp` | Date | Yes | When measurement was recorded |
| `executionTimeMs` | number | Yes | Total execution time |
| `memoryUsageMb` | number | Yes | Peak memory consumption |
| `cpuPercentage` | number | Yes | CPU utilization |
| `metadata.agentType` | string | No | Agent type that executed task |
| `metadata.complexity` | enum | No | Task complexity level |
| `baselineMs` | number | No | Expected execution time |
| `deviationPercent` | number | No | Percent variance from baseline |

## Collection 5: Learnings

### Purpose

Aggregate insights derived from analyzing other collections. High-confidence patterns that guide future decisions.

### Schema Definition

```typescript
interface LearningRecord {
  // Auto-generated fields
  id: string;                          // Unique identifier (UUID)
  createdAt: Date;                     // When insight was generated
  updatedAt: Date;                     // Last update

  // Learning classification
  category: 'pattern' | 'insight' | 'recommendation' | 'optimization';
  title: string;                       // Short learning title
  description: string;                 // Detailed explanation
  applicability: 'general' | 'task-specific' | 'context-dependent';

  // Confidence metrics
  confidence: number;                  // 0.0-1.0 confidence score
  confidenceFactors?: {
    sampleSize: number;                // Number of observations
    consistency: number;               // How consistent the pattern
    recency: number;                   // How recent the evidence
    agreement: number;                 // Cross-validator agreement
  };

  // Evidence
  evidenceCount: number;               // Number of supporting records
  sources?: string[];                  // Which collections provided evidence
  contradictions?: string[];           // Conflicting insights

  // Related data
  tags: string[];                      // Categorization tags
  relatedRecords: {
    decompositions?: string[];         // Related task decompositions
    errors?: string[];                 // Related errors
    security?: string[];               // Related security findings
    performance?: string[];            // Related performance metrics
  };

  // Action items
  actionItems?: Array<{
    description: string;
    priority: 'low' | 'medium' | 'high';
    owner?: string;
  }>;

  // Validity
  validUntil?: Date;                   // When learning may become obsolete
  status: 'active' | 'superseded' | 'disproven' | 'archived';
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `category` | enum | Yes | Type of learning |
| `title` | string | Yes | Learning summary |
| `description` | string | Yes | Detailed explanation |
| `confidence` | number | Yes | 0.0-1.0 confidence score |
| `evidenceCount` | number | Yes | Supporting observations |
| `tags` | string[] | Yes | Categorization tags |
| `relatedRecords` | object | Yes | Links to supporting data |
| `status` | enum | Yes | Current validity status |

## Schema Relationships

### Cross-Collection References

```
Decompositions
    ├─ Stores original task breakdown
    └─ Referenced by Performance metrics (via taskId)

Errors
    ├─ Discovered during task execution
    ├─ Referenced by Security findings (related type)
    └─ Analyzed to create Learnings

Security
    ├─ Discovered during validation
    ├─ Related to Errors (via context)
    └─ Evidence for Learnings

Performance
    ├─ Measured during execution
    ├─ Related to Decompositions (via taskId)
    └─ Evidence for Learnings

Learnings
    ├─ Aggregates all other collections
    ├─ References via relatedRecords
    └─ Highest-level insights
```

### Common Join Patterns

**Pattern 1: Get all data for a task**
```typescript
async function getTaskFullProfile(taskId: string) {
  const client = await getRuVectorClient();

  const decomposition = await client.query.filterSearch('decompositions', { taskId });
  const performance = await client.query.filterSearch('performance', { taskId });
  const errors = await client.query.filterSearch('errors', { 'context.taskId': taskId });

  return {
    decomposition: decomposition[0],
    performance,
    errors
  };
}
```

**Pattern 2: Get all evidence for a learning**
```typescript
async function getLearningEvidence(learningId: string) {
  const client = await getRuVectorClient();

  const learning = await client.learnings.get(learningId);

  const decompositions = await Promise.all(
    (learning.relatedRecords.decompositions || []).map(id =>
      client.decompositions.get(id)
    )
  );

  const errors = await Promise.all(
    (learning.relatedRecords.errors || []).map(id =>
      client.errors.get(id)
    )
  );

  return { learning, supporting: { decompositions, errors } };
}
```

## Schema Evolution

### Handling Schema Changes

**Adding new fields:**
- Old documents missing field will be treated as `undefined` or use defaults
- New inserts include the field
- Use optional types to ensure backward compatibility

**Removing fields:**
- Keep field in schema as deprecated
- Migration: copy data to new field name, deprecate old
- Remove only after verification period

**Renaming fields:**
- Create new field
- Populate via migration script
- Mark old field as deprecated
- Remove after verification
