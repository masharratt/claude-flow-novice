# Trigger.dev Self-Hosted Infrastructure

Complete self-hosted trigger.dev setup for CFN Loop migration. This infrastructure provides a production-ready, multi-service deployment with PostgreSQL, Redis, MinIO, and ClickHouse.

## Quick Start

### Prerequisites

- **Docker**: v20.10+ ([install](https://docs.docker.com/get-docker/))
- **Docker Compose**: v1.29+ ([install](https://docs.docker.com/compose/install/))
- **Git**: For project root detection
- **Bash**: v4.0+
- **Min 4GB RAM**: For all services running simultaneously
- **Min 20GB Disk**: For data volumes (postgres, redis, minio, clickhouse)

### Setup in 3 Steps

1. **Run setup script** (generates secrets and initializes infrastructure):
   ```bash
   ./scripts/trigger-dev-setup.sh
   ```

2. **Wait for health checks** (script will confirm when all services are ready):
   ```
   [SUCCESS] All services are healthy
   ```

3. **Access dashboard**:
   - **Web UI**: http://localhost:3040
   - **API**: http://localhost:3000
   - **MinIO Console**: http://localhost:9001

## Architecture

### Services

| Service | Image | Port | Purpose |
|---------|-------|------|---------|
| **postgres** | postgres:15-alpine | 5432 | Primary database for workflows, triggers, executions |
| **redis** | redis:7-alpine | 6379 | Session management, job queue, caching |
| **minio** | minio/minio:latest | 9000/9001 | S3-compatible object storage for logs, artifacts |
| **clickhouse** | clickhouse/clickhouse-server:latest | 8123/9000 | Time-series analytics for events, metrics, logs |
| **trigger-webapp** | ghcr.io/triggerdotdev/trigger.dev:latest | 3040 | Web UI and REST API server |
| **trigger-worker** | ghcr.io/triggerdotdev/trigger.dev:latest | - | Background job processor for trigger execution |

### Network

- **Network Name**: `trigger-cfn-network`
- **Type**: Bridge network (isolated from host)
- **Service Discovery**: Automatic DNS resolution within network

### Data Volumes

All data is persisted in Docker volumes:

```
postgres_data       → PostgreSQL data
redis_data          → Redis snapshots
minio_data          → S3-compatible object storage
clickhouse_data     → Time-series event data
webapp_data         → Application runtime data
```

## Configuration

### Environment Variables

All configuration is managed via `.env` file. Template variables:

**Database Credentials:**
- `POSTGRES_USER`: PostgreSQL username (default: postgres)
- `POSTGRES_PASSWORD`: PostgreSQL password (must be set)
- `POSTGRES_DB`: Database name (default: trigger)
- `POSTGRES_PORT`: Host port binding (default: 5432)

**Cache & Storage:**
- `REDIS_PORT`: Host port binding (default: 6379)
- `MINIO_ROOT_USER`: MinIO username (default: minioadmin)
- `MINIO_ROOT_PASSWORD`: MinIO password (must be set)
- `MINIO_PORT`: MinIO API port (default: 9000)
- `MINIO_CONSOLE_PORT`: MinIO UI port (default: 9001)

**Analytics:**
- `CLICKHOUSE_DB`: ClickHouse database (default: trigger)
- `CLICKHOUSE_USER`: ClickHouse user (default: default)
- `CLICKHOUSE_PASSWORD`: ClickHouse password (must be set)
- `CLICKHOUSE_PORT`: HTTP port (default: 8123)
- `CLICKHOUSE_NATIVE_PORT`: Native port (default: 9000)

**Application Secrets** (auto-generated by setup script):
- `TRIGGER_SECRET_KEY`: Main application secret key (32 bytes base64)
- `AUTH_SECRET`: Authentication session secret (32 bytes base64)
- `ENCRYPTION_KEY`: Data encryption key (32 bytes base64)
- `MAGIC_LINK_SECRET`: Passwordless login secret (32 bytes base64)
- `JWT_SECRET`: API token signing secret (32 bytes base64)

**Network Configuration:**
- `API_DOMAIN`: API endpoint URL (default: http://localhost:3000)
- `APP_DOMAIN`: Web UI endpoint URL (default: http://localhost:3040)
- `NODE_ENV`: Environment mode (development|production)

**Worker Configuration:**
- `WORKER_ID`: Unique identifier for worker instance (for multiple workers)

### Generate New Secrets

If you need to manually regenerate secrets:

```bash
# Using OpenSSL (recommended)
openssl rand -base64 32

# Using Python
python3 -c "import secrets; print(secrets.token_urlsafe(32))"

# Using Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Update `.env` with new values and restart services:

```bash
docker-compose -f docker/trigger-dev/docker-compose.yml restart
```

### Scale to Production

For production deployments:

1. **Change NODE_ENV**:
   ```env
   NODE_ENV=production
   ```

2. **Update domain configuration**:
   ```env
   API_DOMAIN=https://api.youromain.com
   APP_DOMAIN=https://trigger.yourdomain.com
   ```

3. **Increase resource limits** in docker-compose.yml:
   ```yaml
   services:
     trigger-webapp:
       deploy:
         resources:
           limits:
             cpus: '2'
             memory: 4G
   ```

4. **Configure external database** (optional):
   ```env
   DATABASE_URL=postgresql://user:pass@external-db.example.com:5432/trigger
   ```

5. **Configure external Redis** (optional):
   ```env
   REDIS_URL=redis://external-redis.example.com:6379
   ```

## Troubleshooting

### Services Not Starting

**Symptom**: One or more services fail to start or immediately exit.

**Diagnostic**:
```bash
docker-compose -f docker/trigger-dev/docker-compose.yml ps
docker-compose -f docker/trigger-dev/docker-compose.yml logs --tail=100
```

**Solutions**:
1. Ensure `.env` file exists: `ls -l docker/trigger-dev/.env`
2. Verify secrets are set (not placeholder values)
3. Check disk space: `df -h` (need ~20GB free)
4. Check Docker daemon: `docker info` should succeed

### Health Check Failures

**Symptom**: Script exits with "Services failed to become healthy"

**Diagnostic**:
```bash
docker-compose -f docker/trigger-dev/docker-compose.yml ps
```

**Solutions**:
1. PostgreSQL health check fails:
   - Wait longer: `sleep 30` then manually run `docker-compose ... up -d`
   - Check logs: `docker-compose ... logs postgres`
   - Verify credentials in `.env`

2. Redis health check fails:
   - Check memory: `docker stats redis`
   - Verify volume: `docker volume ls | grep redis`
   - Restart: `docker-compose ... restart redis`

3. MinIO health check fails:
   - Check disk space: `docker volume inspect trigger-dev-minio_data`
   - Verify credentials: Check `MINIO_ROOT_PASSWORD` in `.env`
   - Restart: `docker-compose ... restart minio`

4. ClickHouse health check fails:
   - Check memory: `docker stats clickhouse`
   - Wait longer (needs more startup time): `sleep 60`
   - Check logs: `docker-compose ... logs clickhouse | tail -50`

5. trigger-webapp health check fails:
   - Verify dependencies are healthy first
   - Check API logs: `docker-compose ... logs trigger-webapp`
   - Check port availability: `lsof -i :3040` (if port already in use)

### Port Already in Use

**Symptom**: Error like "Port 3040 already allocated"

**Solution**:
```bash
# Find what's using the port
lsof -i :3040

# Either stop that process or update .env
WEBAPP_PORT=3050  # Use different port
```

### Database Connection Errors

**Symptom**: Webapp logs show "Can't connect to PostgreSQL"

**Solutions**:
1. Check PostgreSQL is healthy:
   ```bash
   docker-compose -f docker/trigger-dev/docker-compose.yml exec postgres pg_isready -U postgres
   ```

2. Verify DATABASE_URL format in logs:
   ```bash
   docker-compose -f docker/trigger-dev/docker-compose.yml logs trigger-webapp | grep DATABASE_URL
   ```

3. Test connection manually:
   ```bash
   docker-compose -f docker/trigger-dev/docker-compose.yml exec postgres \
     psql -U postgres -d trigger -c "SELECT 1;"
   ```

### Memory or CPU Issues

**Check resource usage**:
```bash
docker stats
```

**Solutions**:
1. Reduce allocation in docker-compose.yml
2. Stop non-essential services: `docker-compose down postgresql redis`
3. Check available system memory: `free -h`
4. Clear Docker cache: `docker system prune -a` (use carefully)

### Cannot Access Web UI

**Symptom**: http://localhost:3040 doesn't respond

**Solutions**:
1. Verify service is running:
   ```bash
   docker-compose -f docker/trigger-dev/docker-compose.yml ps trigger-webapp
   ```

2. Check if port is listening:
   ```bash
   curl -I http://localhost:3040 || echo "Connection refused"
   ```

3. Try using service name from within container:
   ```bash
   docker-compose -f docker/trigger-dev/docker-compose.yml exec trigger-webapp \
     curl -I http://localhost:3000
   ```

4. Check APP_DOMAIN in `.env` matches your access URL

### Webapp API Errors

**Symptom**: HTTP 500 error when accessing API endpoints like `/api/v1/status`:
```
TypeError: Cannot read properties of undefined (reading 'features')
```

**Root Cause**:
1. The `/api/v1/status` endpoint doesn't exist in trigger.dev
2. Missing self-hosted configuration variables

**Solutions**:
1. **Use legitimate endpoints** - test these instead:
   ```bash
   curl -I http://localhost:3040/login    # Should return 200
   curl -I http://localhost:3040/         # Should return 302 (redirect)
   ```

2. **Add missing self-hosted configuration** to `.env`:
   ```env
   # Self-hosted configuration
   TRIGGER_TELEMETRY_DISABLED=false
   TRIGGER_SELF_HOSTED=true
   TRIGGER_FEATURES_REAL_TIME=true
   TRIGGER_FEATURES_CATALOG=true
   TRIGGER_FEATURES_WEBHOOKS=true
   TRIGGER_FEATURES_BATCHES=true
   TRIGGER_FEATURES_SCHEDULED=true

   # Organization settings
   TRIGGER_ORG_SLUG=cfn-b36c
   TRIGGER_PROJECT_SLUG=cfn
   TRIGGER_ORG_ID=cmi8xpmpv0002r25mzsrdbu3j
   TRIGGER_PROJECT_ID=cmi8xpmpz0005r25m7no4zpht
   ```

3. **Restart services** after updating `.env`:
   ```bash
   docker-compose down
   docker-compose up -d
   ```

4. **Verify webapp is working**:
   ```bash
   # Check login page loads completely
   curl -s http://localhost:3040/login | head -20

   # Verify environment variables are loaded
   docker-compose exec trigger-webapp printenv | grep TRIGGER_SELF_HOSTED
   ```

**Additional Documentation**: See `CLAUDE.md` for detailed troubleshooting and development workflow.

## Integration with CFN Loop

### Environment Variable Injection

When spawning CFN Loop agents, inject trigger.dev credentials:

```bash
export TRIGGER_API_URL="http://localhost:3000"
export TRIGGER_WEBHOOK_URL="http://localhost:3040/webhooks"

# For agent spawning
npx claude-flow-novice agent-spawn orchestrator-task \
  --env TRIGGER_API_URL="$TRIGGER_API_URL" \
  --env TRIGGER_WEBHOOK_URL="$TRIGGER_WEBHOOK_URL"
```

### Webhook Configuration

For CFN Loop triggers via webhook:

```
Webhook URL: http://localhost:3040/webhooks/cfn-loop-{TASK_ID}
API URL:     http://localhost:3000
Authentication: Bearer {JWT_SECRET}
```

## Blockers

### BLOCKERS

1. **Image Availability**: This setup uses `ghcr.io/triggerdotdev/trigger.dev:latest` which requires:
   - Internet connectivity to pull from GitHub Container Registry
   - Valid GHCR credentials if image is private
   - **Runtime Testing Required**: Verify image pulls successfully and starts without errors
   - **Workaround**: Pre-pull image or build from source if GHCR not accessible

2. **Health Check Endpoints**: The docker-compose.yml assumes specific health check endpoints:
   - PostgreSQL: `pg_isready` command
   - Redis: `redis-cli ping` command
   - MinIO: `http://localhost:9000/minio/health/live` endpoint
   - ClickHouse: `http://localhost:8123/ping` endpoint
   - trigger-webapp: `http://localhost:3000/health` endpoint
   - **Runtime Testing Required**: Verify all health check endpoints respond as expected
   - **Workaround**: If endpoints differ, update docker-compose.yml `healthcheck` sections

3. **Secret Generation Methods**: Setup script tries multiple secret generation methods:
   - `openssl rand -base64 32` (preferred)
   - Python3 `secrets` module
   - Node.js `crypto` module
   - **Runtime Testing Required**: Verify at least one method is available on target system
   - **Workaround**: Pre-generate secrets manually and update `.env` before running setup script

4. **Port Availability**: Default port assignments may conflict with existing services:
   - PostgreSQL: 5432
   - Redis: 6379
   - MinIO API: 9000
   - MinIO Console: 9001
   - ClickHouse HTTP: 8123
   - ClickHouse Native: 9000 (conflicts with MinIO)
   - trigger-webapp: 3040
   - **Runtime Testing Required**: Verify ports are available before setup
   - **Workaround**: Update port numbers in `.env` and docker-compose.yml if conflicts exist

5. **Docker Network Isolation**: Services communicate via Docker service DNS (not localhost):
   - All internal connections use service names (postgres, redis, minio, clickhouse)
   - Host machine connections use localhost:PORT
   - **Runtime Testing Required**: Verify service discovery works within Docker network
   - **Workaround**: For debugging, connect directly to container IPs if DNS fails

6. **Volume Permissions**: Docker volumes may require host user to have write permissions:
   - Linux systems may need `docker` group membership or `sudo`
   - **Runtime Testing Required**: Verify volumes can be created and written to
   - **Workaround**: Run with `sudo` or adjust Docker daemon socket permissions

7. **Trigger.dev Initialization**: First startup performs database migrations:
   - May take 30-60 seconds for webapp to be ready
   - Database schema is created on first run
   - **Runtime Testing Required**: Verify migrations complete successfully
   - **Workaround**: Increase health check timeout or run migrations separately if needed

## Performance Notes

- **Cold Start**: Initial startup takes 2-3 minutes (dependencies, migrations)
- **Resource Usage**: ~2GB RAM with all services running (can be reduced)
- **Database Growth**: Unindexed queries on large datasets may be slow
- **Analytics**: ClickHouse needs proper retention policies for long-term storage

## Security Considerations

- All secrets are auto-generated (strong cryptographic randomness)
- Services only communicate over isolated Docker network
- MinIO credentials are randomized (separate from system passwords)
- Secrets are stored in `.env` (add to `.gitignore`)
- No hardcoded passwords in configuration files
- For production, use environment secret management (Vault, AWS Secrets Manager, etc.)
